# FDE Playbook：四步法展开

## 第 1 步：蹲现场（不在会议室定需求）

**做什么**：去业务岗位旁边，看半天真实操作。

- 看操作序列：真实的一天/一个任务怎么走的，不是"应该"怎么走的
- 记下断点：哪里卡、哪里等、哪里靠人肉、哪里重复
- 记下数据形态：用的什么表/系统/纸面，谁能拿，多久更新一次
- 别问"你想要什么 AI 功能"——问"你哪一步最烦、最重复、最等不起"

**产出**：一段观察记录 + 一个"最烦环节"候选（场景卡的业务环节来源）。
**反例**：会议室里 PPT 定需求 → 定出来的需求是想象出来的流程，不是真实流程。

## 第 2 步：1 页场景卡

把问题压成一页，现场/立项拿来对账：

```markdown
# 场景卡：<环节名>
业务环节：______（一句话，如"报价单生成"）
现状耗时/人力：______（每张/每天/每次 多少）
数据在哪、能不能拿：______（系统/表/人，权限，更新频率）
试过什么、卡在哪：______（别假设没试过，先承认已知）
成功长什么样（可量化指标）：______（准确率/耗时/采纳率，带数字）
推动方：______（业务负责人 or IT）——决定能不能活
```

**判读**：五项有一项填不出 = 问题还没被真实击中，回蹲现场。"可量化指标"填不出 = 这个环节结果不可判定，不该选。

## 第 3 步：拆到最小 + 固定 5 问

**选环节三条件**（缺一不切）：
- **高频**：重复发生，收益能被重复兑现
- **低风险**：错了能兜住，不会造成不可逆损失
- **结果可判定**：做得好不好有明确数字，不是"感觉不错"

**固定 5 问**（每个候选都过，横向对比用同一组）：

| # | 问题 | 判读 |
|---|---|---|
| 1 | 数据从哪来、谁有权用？ | 拿不到数据 = 别做；有权但脏 = 先清洗 |
| 2 | 最小闭环做到多小才敢上线？ | 越小越好；"最小"要能一句话描述 |
| 3 | 错了怎么办（兜底+人工复核）？ | 答不出 = 不许上自动化 |
| 4 | 成本怎么算（token/人力/返工）？ | 返工成本 > 节省成本 = 不划算 |
| 5 | 谁在推——业务还是 IT？ | **最关键**：IT 单推业务不用 = 活不过两个季度 |

## 第 4 步：48 小时最小小样

**只交付一件东西**（不要长篇纪要）：

```markdown
# 小样：<环节名>
1. 提示词/模板：<可复用的 prompt 或工具配置>
2. 10 条真实数据测试记录：
   | # | 输入 | 输出 | 人工判定(对/错) | 备注 |
   |---|---|---|---|---|
   | 1 | ... | ... | 对 | |
   | ... | | | | |
3. 对比数字：
   - 准确率：<对/10>
   - 单条耗时：AI <x> vs 人工 <y>
   - 返工率：<需人工修正的条数/10>
```

**使用方评判**：拿去给业务同事看。判据不是"技术方说能用"，而是：
- 使用方说"我明天就想用" = 真痛点
- 使用方说"再观察观察" = 伪痛点，回蹲现场

## 第 5 步：人工兜底 → 自动化

兜底机制**写进流程**（不是靠自觉）：
```
AI 出草稿 → 人工复核（谁？什么条件放行？错了回退到哪？）
  → 跑够 N 条样本 → 统计自动放行比例
  → 比例稳定且高 → 才谈去掉人工环节
```

## 第 6 步：量化再复制

**有数字才复制第二环节**：
```
第一环节数字（准确率/耗时/使用方采纳/返工率）
  → 达标 → 第二环节走完整流程（场景卡→小样→兜底→数字）
  → 不达标 → 停在试点，回查拆法/兜底/数据
```

**复制 = 全流程重走一遍**，不是把第一环节的模板直接搬过去（不同环节数据形态/风险不同）。
