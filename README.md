# fde-business-embed

FDE（前置部署工程师）方法论技能：企业 AI 的瓶颈不在模型，而在"没人把模型翻译成流程"——用蹲现场/拆到最小/先人工兜底/量化再复制四步法，把 AI 真正编进业务工作流。

一句话：**AI 不是"买了个工具"，是真被编进了工作流。**

## 方法论底座

- 题眼：企业 AI 的瓶颈已从"模型够不够强"转移到"有没有人能把它塞进业务现场"
- FDE 由 Palantir 发扬，OpenAI/Anthropic 标配：既懂技术又蹲业务现场的翻译官
- 来源活动：AI 知声 FDE 线下沙龙（小而密闭门，33 人报名/850 浏览，重交流密度而非声量）
- 核心动作：从"剪/学"变成"填场景卡 + 做小样 + 对数字"

## 解决什么

| 痛点 | 本技能的做法 |
|---|---|
| AI 落地不知道从哪下手 | 决策前置：手上没有"具体的、AI 还没跑通的业务环节"就不立项 |
| 会议室里定需求，业务不认 | 蹲现场看真实操作，需求来自"哪一步最烦/最重复/最等不起" |
| 试点选太大，跑不出数字 | 拆到最小：一个高频+低风险+结果可判定的环节 |
| 上线即翻车 | 先人工兜底：AI 出草稿人拍板，兜底写进流程（谁复核/放行条件/回退点） |
| 长篇纪要代替成果 | 48 小时小样三件套：提示词模板+10 条真实数据记录+准确率/耗时对比 |
| 技术方说能用就算闭环 | 使用方评判：业务同事说"明天就想用"才算 |
| 感觉不错就推第二环节 | 量化再复制：有数字才复制，没数字停试点 |
| IT 单推活不过两个季度 | 推动方必须是业务负责人（第 5 问最关键） |

## 安装

复制本目录到 `~/.agents/skills/`（或你的 Skill 加载路径）即可。

## 自检

```bash
python scripts/validate.py tests/sample_good.json   # 必须 exit 0
python scripts/validate.py tests/sample_bad.json    # 必须 exit 1
```
